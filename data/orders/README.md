# 陈政铭的洗衣订单样本

本目录保存个人离线数据准备工具与一份可复现的模拟 CSV，供 ORD-01 至 ORD-10 核对。需求见 D04 的 DAT-01 至 DAT-04。Kafka 的持续发送和 Flink 分析属于后续正式模块。

## 生成规则

- 默认从 2026-11-16 起生成 7 天，每天 08:00 至 20:00 接受 144 笔订单，共 1,008 单。各时段按不同权重抽取下单时刻，晚高峰更集中，站点 S01 与 S02 各有 4 台机器。模型允许收班后完成已经排队的订单。
- 使用固定 seed 的随机数发生器。对每个站点按订单到达顺序分配最早可用的机器。若预计等待超过该顾客的耐心时长，则在耐心耗尽时取消，机器可用时刻不变。成功开洗才占用机器，工序运行时间随洗涤程序变化。
- 每个订单依次产生 QUEUED → STARTED → COMPLETED 或 QUEUED → CANCELLED。开洗和完成使用同一台机器；实收仅在完成时出现。机器在同一时刻完成旧订单后可以开始下一单。
- 先生成业务事件，再按事件时间稳定排序。时间格式为东八区本地时间 YYYY-MM-DD HH:mm:ss.SSS。按订单号和事件类型构造唯一事件 ID。更换参数且日期重叠的文件属于替代样本，导入时应隔离批次。
- 文件编码为 UTF-8，使用逗号与首行字段名。字段依次为 event_id、order_id、site_id、machine_id、event_type、event_time、queued_at、program、paid_amount。未分配机器时 machine_id 为空。价格与运营情景仅作课程模拟。
- 默认参数的核对条件：1,008 个不同订单、2,016 至 3,024 条事件；事件编号唯一、队列时间固定、状态流转合法、金额精确到分、同一机器服务区间不交叠。具体行数随随机种子变化。

## 运行

在仓库根目录用 Python 3.8 或更高版本运行；仅使用标准库。

```text
python data/orders/generate_orders.py
python data/orders/generate_orders.py --start-date 2026-11-16 --days 1 --orders-per-day 40 --seed 27 --output data/orders/sample.csv
```

默认输出到脚本同目录的 orders.csv。重新运行会原子替换指定输出文件。原始七日样本提供事件数量和合理体量，现场的实时入流还需按节奏持续生产。生产者后续读取 CSV 时应将空机号转为 null，保留业务时间与金额精度。
